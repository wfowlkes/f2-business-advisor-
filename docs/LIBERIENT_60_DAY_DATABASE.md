# LIBERIENT – database-backed two-month synthetic demonstration

## What was built

A built-in SQLite database seeded with exactly **60 completed UTC calendar days** of **synthetic** aggregated retail data, generated by a versioned deterministic fixture (`experience/demo60.js`). It is available on the free Render development service at `/api/demo60` **only when** `F2_DEMO_MODE=true`. The existing customer UI at `/experience/` automatically loads this source. Static GitHub Pages uses an identical **local generator fallback** and clearly identifies that no database is connected.

The simulated business has baseline sales, a promotional increase, a shortage-related decline, and subsequent recovery. Each daily record stores net sales, aggregate order count, synthetic refunds, new and returning customer-order activity, available inventory units and affected stockout-product count. All values are made up. There are no real customer records, names, email addresses, order IDs or Shopify credentials. A `phase` field is retained in the internal fixture for deterministic unit tests but removed from the public API so the UI cannot mistake its simulator's ground-truth label for a detected business condition.

SQLite is **in-memory** on Render's free tier. This is a genuine SQL database but **not durable merchant storage**; it is recreated from the same synthetic generator on server restart and advances to the previous completed UTC day after midnight. It is not a managed long-term database, and restarting the host does not preserve user-entered data. The tracker layout may be saved to the current device's local storage, but imported CSV data and merchant keys are not saved by this module.

## Supported customer features

- Revenue, orders, returns, customer-order activity and inventory cards when source and type checks pass
- Separate correctly sourced 3D-inspired revenue, order, customer, inventory and refund mini-graphs
- Two-month browsing, customizable and reorderable signal stream, 7/30-day **illustrative** projected revenue
- Observed change-point visual markers, quick local aggregate-only business answers
- Source provenance and bounded in-browser interaction/adaptation log
- Source-gating: arbitrary CSV imports never unlock customer or inventory features; future features require verified input/field permissions

The 7/30-day projection uses the preexisting F2 same-weekday reference model on 60 complete daily records. It does **not** pass robust pregame-style chronological 180/365-day evaluation and is **not authorized for operational decision-making**. It is explicitly research-only and displays HOLD. The original full F2 evaluation and other Learning Lab experiments remain unchanged.

## Read-only and privacy boundaries

- `GET /api/demo60`: public **synthetic-only**, allowed only when `F2_DEMO_MODE=true`; never returns live Shopify data or secrets.
- `GET /api/snapshot`: remains protected by the existing private dashboard key; unaffected.
- ChatGPT: disabled unless an approved separate server integration is configured. Local questions are answered from currently loaded aggregate numbers without network model calls.
- No API endpoint mutates the database or allows arbitrary SQL queries.
- Predictive model changes require distinct prospective tests, accountable evidence and explicit authorization.

## Tests

Run `node --test server/test/demo_database.test.js server/test/demo_api.test.js` or the existing Render build command for all backend suites. Checks verify complete chronological daily records, deterministic reproducibility, schema/no PII, midnight refresh, provenance, source gating, guarded access, policy HOLD, feature enabling only when fields exist and original private API isolation.
